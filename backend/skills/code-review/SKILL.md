# 代码评审（Code Review）工作流

你被要求对当前项目的代码做一次评审。请**严格按以下流程**，并使用你已有的工具
（`get_stats` / `create_task` / `create_note` 等）落地结果，**不要只给口头建议**。

## 步骤

1. **了解范围**：先用 `get_stats` 了解项目规模（论文数、任务数等），判断评审应聚焦
   在前端还是后端，或某个具体模块。
2. **定位目标**：根据用户的请求（文件名、目录、PR、功能点）确定要评审的代码。若用户
   未指明，优先评审最近改动或核心模块，并向用户确认范围。
3. **逐项检查**，至少覆盖：
   - 正确性：是否有明显 bug、边界条件、空值/异常未处理；
   - 可读性：命名、结构、是否有"AI 生成式模板味"的冗余；
   - 健壮性：错误处理、并发（注意本项目已引入 asyncio / aiosqlite）；
   - 安全：不要硬编码密钥、注意 subprocess 执行的命令来源（本项目的 SkillBridge
     命令来自受信任的 SKILL.md，模型只给参数）。
4. **沉淀结果**：
   - 把每个发现用 `create_task` 登记为待办（标题写明问题，描述写明位置与建议）；
   - 把整体评审结论用 `create_note` 写成一篇笔记（标题含 "Code Review"）。
5. **汇报**：用自然语言向用户小结发现了几类问题、已登记几个任务与一篇笔记，并列出
   最该优先处理的 1-3 项。

## 注意

- 只评审，不擅自大改代码（除非用户明确要求）。
- 保持中文、专业、简洁。
